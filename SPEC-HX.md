# `.hx` — Serpent for plain JavaScript

Same language, same compiler, different target. `.hsx` compiles to React TSX;
`.hx` compiles to plain JavaScript.

```
.hsx  ->  React TSX   (components, JSX trees)
.hx   ->  JavaScript  (functions, scripts, node programs)
```

---

## 1. What is shared

Everything lexical and structural is identical, because it is literally the same
compiler front end:

- Significant indentation, `INDENT`/`DEDENT` tokens, consistent width per file
- `#` comments
- `def`, `if`/`elif`/`else`, `for`, `return`, `import`/`from`
- `lambda`, list/dict literals, comprehensions
- f-strings -> template literals
- `==`/`!=` -> `===`/`!==`, `and`/`or`/`not` -> `&&`/`||`/`!`
- Python builtins: `len`, `str`, `int`, `sum`, `sorted`, `strip`, `upper`, ...
- The same compiler binary. `serpent foo.hx` picks the JS target by extension.

---

## 2. What `.hx` adds

Constructs that make no sense inside a component tree but are essential for
general-purpose code:

```serpent
# while loop
def countdown(n: int):
    while n > 0:
        print(n)
        n -= 1
    print("liftoff")

# break / continue
def first_even(xs):
    for x in xs:
        if x % 2 != 0:
            continue
        return x
    return None

# try / except
def safe_parse(text):
    try:
        return int(text)
    except ValueError:
        return None
    finally:
        print("done")

# async / await
async def load_user(user_id):
    response = await fetch(f"/api/users/{user_id}")
    return await response.json()

# export
export def greet(name: str) -> str:
    return f"Hello, {name}!"

export PI = 3.14159
```

---

## 3. What `.hx` removes

- **`component`** — there is no component tree. A `component` in a `.hx` file is a
  compile error with a hint pointing at `.hsx`.
- **Tree blocks** — `div:` / `h1: "x"` is not a construct here. A bare `name:`
  followed by an indented block is a syntax error, because in JS there is no
  element to nest.
- **JSX prop mapping** — no `on_click` -> `onClick`, no `cls` -> `className`.
  Attribute names are passed through unchanged.

---

## 4. Output shape

```serpent
def add(a: int, b: int) -> int:
    return a + b

result = add(2, 3)
print(f"sum is {result}")
```

```js
// [xihanzu-NR]
// GENERATED by serpent — edit the .hx file, not this one

function add(a, b) {
  return (a + b);
}

const result = add(2, 3);
console.log(`sum is ${result}`);
```

Notes:
- `def` becomes a hoisted `function` declaration in `.hx` (not a `const` arrow),
  so mutual recursion works without ordering gymnastics.
- Type annotations are erased. There is no type checker in the JS target; a
  `.hx` file is not type-checked by `tsc`.
- `export def` becomes `export function`.

## 5. Runtime

`.hx` output imports from `serpent-js` only when it uses something the compiler
cannot inline:

```js
import { range, enumerate, zip, truthy } from 'serpent-js'
```

| Export | Python meaning |
|---|---|
| `len`, `sorted`, `reversed`, `sum` | runtime fallbacks for the compile-time rewrites |
| `range(a, b, step)` | Python `range` semantics |
| `enumerate(xs)` | `[[0, x0], [1, x1], ...]` |
| `zip(a, b)` | truncated to the shorter input |
| `truthy(x)` | empty list/dict/string and 0 are falsy |
| `dict_get(o, k, fallback)` | attribute access that will not throw |

`print` compiles to `console.log` with no import.

---

## 6. Why one compiler, not two

The lexer, parser and error machinery are the expensive parts and they are
identical. Only the emitter differs. Keeping them in one binary means:

- One grammar to document, one test suite for the front end
- A fix to indentation handling fixes both languages
- `parity.py` can diff both targets against both references

The cost is one `Target` enum threaded through the emitter, which is far less
than a second parser would be.

---

## 7. Non-goals

- **Not TypeScript.** `.hx` erases types. If you want types, use `.hsx` (which
  emits TSX and is checked by `tsc`) or write `.ts`.
- **Not a Node framework.** No router, no server, no build system. It is a
  syntax for JavaScript, nothing more.
- **No classes yet.** `class` is reserved but unimplemented; adding it is a
  parser change plus an emitter case, deferred until something needs it.
