# HydraScript

**A Pythonic syntax for React, compiled by a native Rust binary.**

[![npm](https://img.shields.io/npm/v/hydrascript.svg)](https://www.npmjs.com/package/hydrascript)
[![license](https://img.shields.io/npm/l/hydrascript.svg)](LICENSE)

[npm](https://www.npmjs.com/package/hydrascript) | [English](README.md) | [Bahasa Indonesia](README.id.md)

---

## What this is

HydraScript compiles indentation-based `.hyx` files to React TSX and `.hys` files
to plain JavaScript. The compiler is a Rust binary; a small Node runner wraps
esbuild, PostCSS and Tailwind to produce a site.

Status: **0.4.0, pre-1.0.** The language works and is tested; it is not
battle-tested at scale, and the file-based router and language server described
in older documents do not exist yet. Treat this as usable-if-you-like-it, not
production-hardened.

### The syntax is frozen at 0.3

No new language features are planned before 1.0. That is a decision, not
inertia: a small language earns trust by standing still long enough for people
to build on it, and every added construct is an emitter path to maintain
forever. What changes between now and 1.0 is plumbing, not syntax: the build,
the dev server, diagnostics, bundler integration, CI, and type declarations. If
an idea needs new syntax, the answer is almost always no.

Breaking changes still happen, and every one of them carries a codemod or a
migration note. No exceptions, even with few users: projects die because people
stop daring to upgrade, not because of missing features.

## A 30-second example

```python
# [xihanzu-NR]
from hydra import state

component Counter(start: int = 0):
    count, set_count = state(start)

    div(className="counter"):
        h2: f"Value: {count}"
        button(onClick=lambda: set_count(count + 1)): "Add"
```

compiles to (verbatim compiler output, base64 source-map footer trimmed):

```tsx
// [xihanzu-NR]
// GENERATED by hydra — edit the .hsx file, not this one
import { state } from 'hydra';

export function Counter({ start = 0 }: CounterProps) {
  let [count, set_count] = state(start);
  return (
    <div className="counter">
      <h2>{`Value: ${count}`}</h2>
      <button onClick={(() => set_count((count + 1)))}>Add</button>
    </div>
  );
}

export interface CounterProps {
  start?: number;
}
```

No virtual machine, no interpreter: the output is ordinary React. The only
HydraScript-specific thing in it is the `hydra` import, and that import appears
only when the file actually calls a helper.

## Honest comparison with TSX

HydraScript is shorter for the things JSX is verbose about, and neither better
nor worse for everything else. This is the actual shape of the trade:

| Area | TSX | HydraScript | Verified how |
|---|---|---|---|
| Element nesting | Closing tags | Indentation | Read the emitted TSX |
| Multi-branch UI | Nested ternaries / IIFE switch | `if / elif / else`, `match` | Compiled both |
| Dynamic classes | `clsx(...)` import | `cls={...}` dict, no import | Emitted `cx(...)` |
| Event prevent/stop | Manual `e.preventDefault()` | `on_submit_prevent_stop=fn` | Emitted both calls |
| List rendering | `.map()` + `key` | `for x in xs:` + `key=` | Emitted `.map()` |
| String interpolation | Template literals | f-strings | Emitted template literal |
| State | `const [v, setV] = useState()` | `v, set_v = state()` | Emitted `useState` |
| Multiple roots | Manual `<>...</>` | Automatic | Emitted fragment |
| Token count for the same component | 188 tokens | 130 tokens | `benchmarks/tokens.py` |

The last row is measured on one component in the repo, not a corpus — see the
next section for exactly what is and is not claimed.

One correction worth stating because it surprises people: `count && <Badge/>`
renders `0`, not nothing. The compiler emits `count && (<span>…)` exactly like
TSX does. Use `if count:` when you want the guard.

## Syntax reference

### Indentation

`h1: "text"` puts one child inline. A trailing `:` with an indented block nests:

```python
div(className="container"):
    header(className="header"):
        h1: "System Status"
        p: "All telemetry nodes online."
```

### Multiple roots

Siblings at the top of a component wrap in a fragment automatically:

```python
component MetricPair(label: str, value: str):
    span(className="label"): label
    span(className="value"): value
```

```tsx
export function MetricPair({ label, value }: MetricPairProps) {
  return (
  <>
    <span className="label">{label}</span>
    <span className="value">{value}</span>
  </>
  );
}
```

### Props and events

`class` / `cls` → `className`, `for` → `htmlFor`, `tab_index` → `tabIndex`,
`on_click` → `onClick`, `on_change` → `onChange`, `on_submit` → `onSubmit`,
`on_key_down` → `onKeyDown`. `aria_*` and `data_*` keep their hyphens.

Suffixes add the boilerplate for you:

* `on_submit_prevent=fn` → `e.preventDefault()` then `fn(e)`
* `on_click_stop=fn` → `e.stopPropagation()` then `fn(e)`
* `on_click_prevent_stop=fn` → both

### Dynamic classes

```python
div(cls={"btn": True, "active": is_active, "muted": not is_active}): "Hi"
```

emits `className={cx({...})}` with `cx` imported from `hydra`.

## Language features

Python semantics are preserved rather than approximated. Each of these is
covered by a test in `compiler-rs/tests/compile.rs`:

```python
a = 0 < x < 10              # chained comparison
found = key in items        # membership, not property presence
same = a is b               # identity
a, b = b, a                 # parallel assignment
p = q = r = 0               # chained assignment
name, age = get_user()      # destructuring
xs[1:3] / xs[:5] / xs[::2]  # slicing
{k: v for k, v in pairs}    # dict comprehension, tuple targets too
{x for x in xs}             # set comprehension
total = 0
for x in xs:
    total += x              # augmented assignment on any target
```

`def` containing `yield` becomes a generator (`function*`). `class` with
`__init__` becomes an ES class (`this`, `@staticmethod`, inheritance).
`@deco` becomes `f = deco(f)`. `@dataclass` synthesises `__init__` from the
annotated fields.

`slot` in a component body renders `props.children` and adds `children` to the
props type:

```python
component Card(title: str):
    div(className="card"):
        h3: title
        slot
```

### Error types

`class MyError(Exception)` produces a real JS class, and `raise` keeps a usable
stack trace:

```python
class ValidationError(Exception):
    pass

def check(x):
    if x < 0:
        raise ValidationError("negative")
```

### The `.hys` side

`.hys` files compile to plain JavaScript — no React, no JSX. Useful for scripts
and Node utilities:

```python
from "node:fs/promises" import readFile

async def count_lines(path: str):
    raw = await readFile(path, "utf8")
    return len(raw.split("\n"))
```

Run one directly with `hydra run script.hys`.

## Runtime (`hydra`)

Both the compiler's helpers and the React adapters come from a single
specifier, `hydra`, which resolves to `runtime/hydra.ts`.

**Three specifiers, and the compiler enforces which one you may use where:**

| import from | holds | allowed in |
|---|---|---|
| `hydra` | universal helpers (`state`, `fetch_json`, `mount`, `Router`) | any module |
| `hydra/server` | `env`, `read_text`, `write_text`, `redirect`, `action_flow` | a `.server.hys` only |
| `hydra/client` | `window_size`, `scroll_to`, `local_storage`, `clipboard` | a `.hyx`/`.tsx` only |

Importing `hydra/server` from a page is a **build error that names the file and
says why**, not a stack trace at run time:

```
[hydra] src/pages/index.hyx imports "hydra/server".
        A page is bundled for the browser, so a server-only module cannot be
        reached from it. Move the code into src/pages/index.server.hys and read
        the value from a loader instead.
```

The reverse is checked too: `hydra/client` in a `.server.hys` fails, because
there is no `window` there. This is the compiler refusing an import it can prove
is wrong, which is the only kind of import it refuses.

| Function | React API |
|---|---|
| `v, set_v = state(init)` | `useState` |
| `r = ref(init)` | `useRef` |
| `cb = callback(fn, deps)` | `useCallback` |
| `effect(fn, deps)` | `useEffect` |
| `v, toggle_fn, set_v = toggle(False)` | custom (3-tuple, not 2) |
| `is_mounted = use_mounted()` | custom |

The runtime also exports ~150 smaller helpers (`debounce`, `fetch_json`, `cx`,
`get_path`, `use_dark_mode`, …). `hydra doctor` and `hydra list` are the quickest
way to see what a project actually has.

**Do not name your own runtime file `src/hydra.hys`.** The specifier `hydra` is
the compiler's contract; a project file cannot satisfy every helper the compiler
can emit, and shadowing it fails with `No matching export in src/hydra.hys for
import len_of`. Import project code by relative path.

## Built-in functions

These need no import:

| HydraScript | Emits |
|---|---|
| `len(xs)` / `len(d)` | `xs.length` / dict-aware `len_of(d)` |
| `max(a, b)` / `max(xs)` | `Math.max(a, b)` / spread |
| `min(a, b)` / `min(xs)` | `Math.min(a, b)` / spread |
| `abs(x)` / `round(x)` | `Math.abs` / `Math.round` |
| `pow(a, b)` | `a ** b` |
| `sum(xs)` / `sum(xs, start)` | reduce / runtime helper |
| `sorted(xs)` / `reversed(xs)` | non-mutating |
| `str` / `int` / `float` / `bool` | `String` / `parseInt` / `parseFloat` / `Boolean` |
| `isinstance(x, int)` | `isinstance(x, Number)` |
| `type(x).__name__` | `x.constructor.name` |
| `enumerate` / `range` / `zip` | runtime helpers, auto-imported |
| `xs.some(lambda x: x > 2)` | `xs.some((x) => x > 2)` |
| `print(x)` | `console.log(x)` |
| `assert cond, "msg"` | `assert_(cond, "msg")` — throws |
| `raise ValueError("x")` | `raise_(new ValueError("x"))` |

Python string methods with no JS equivalent (`s.capitalize()`, `s.zfill(4)`,
`s.isdigit()`) and collection helpers (`", ".join(xs)`, `d.get(k, v)`,
`xs.extend(ys)`) call into the runtime. The import is injected for you. Helpers
delegate to a receiver that owns the equivalent method, so `.add()` / `.remove()`
stay safe on non-list objects like `DOMTokenList`.

### Constructors

Python has no `new`; browser APIs need it, so it is part of the language:

```python
def setup():
    obs = new IntersectionObserver(on_change, {"threshold": 0.25})
    obs.observe(el)
    return obs
```

`fn?.(x)` compiles to an optional call.

### Module imports

```python
from "react" import useState, useEffect   # named import
from "./Header.hyx" import Header         # local component
import "./index.css"                      # side-effect
from "./logo.svg" import logo             # asset: default import
export component Button(label: str):      # exported component
    button: label
export def tax(amount):                   # exported function
    return amount * 0.11
```

## Components and JSX output

A `component` becomes an exported React function component with a matching
`Props` interface. Prop defaults map to destructuring defaults. `self` is `this`,
`__init__` is the constructor, and `super().__init__(x)` becomes `super(x)`.

Output validation: every emit is checked before it leaves the compiler
(`src/validate.rs`). It rejects shapes that are always invalid JavaScript — a
declaration whose target is a member expression, `new` with nothing to
construct, unbalanced brackets in plain-JS output. A failure here is a compiler
bug and the message says so. This exists because the compiler once reported
success for output no JS engine would accept.

## Meta-framework

**`hydra dev`, `build` and `preview` use esbuild, not Vite.** PostCSS,
Autoprefixer and Tailwind are driven programmatically, so a project needs no
`vite.config.ts`, `tailwind.config.ts` or `postcss.config.js`.

| Command | Does |
|---|---|
| `hydra dev` | Builds, serves, rebuilds on change, live-reloads the browser |
| `hydra build` | Production build: hashed assets, minified CSS, SSG |
| `hydra preview` | Serves `dist/` (builds first if it is missing) |
| `hydra run <file.hys>` | Executes a script in-process |

**On "HMR":** `hydra dev` watches `src/`, rebuilds, and **reloads the page in the
browser over a websocket** — no dependency, no browser extension, ~10 seconds
from save to reload. What it does *not* do is preserve component state across a
change: a successful edit reloads, it does not hot-swap the module. Calling that
React Fast Refresh would be wrong, so this README calls it live reload.

**A failed rebuild does not reload.** It sends the error to the page instead, so
the console shows the compiler's message with the file and line, and you keep the
last working page until the code compiles again.

### File-based routing

`src/pages/` is the route table. The filename decides the URL, and `hydra routes`
prints the result so that none of it is hidden.

```
src/pages/index.hyx             -> /
src/pages/about.hyx             -> /about
src/pages/blog/index.hyx        -> /blog
src/pages/blog/[slug].hyx       -> /blog/:slug
src/pages/docs/[...rest].hyx    -> /docs/*      (one segment or more)
src/pages/files/[[...rest]].hyx -> /files/*     (also /files)
src/pages/(marketing)/price.hyx -> /price       (group: layout scope only)
src/pages/_partials/Hero.hyx    -> not routable
```

`_layout.hyx` wraps every route in its folder and below, `_404.hyx` renders when
nothing matches, and `_error.hyx` is the error boundary for its folder. All three
may appear at several levels; the nearest one wins.

Two files that claim the same URL are a **build error naming both files**, not a
race decided silently. That covers `blog/[slug].hyx` + `blog/[id].hyx` (one URL
position, two parameter names) and `about.hyx` + `about/index.hyx` (one URL, two
files).

The directory is configurable through `"routes"` in `hydraconfig.json`, or turned
off with `"routes": false`.

### Pre-rendering, per route

**A build writes one HTML file per static route**: `dist/about/index.html`, not
one `dist/index.html` for the whole site. Dynamic routes are skipped and **named**
in the build log, because a URL with a parameter has no single page to build:

```
[hydra] 4 route(s) from src/pages, 1 dynamic (/blog/:slug)
[hydra] SSG: pre-rendered 3/3 static route(s) into dist/
[hydra] SSG: 1 dynamic route(s) left as the client shell (/blog/:slug) —
        a URL with a parameter has no single page to build
```

The runtime gate now loads **every** `index.html` the build produced, not only the
root one: with per-route HTML, checking one page leaves every other route
unchecked, which is exactly where a route bug lives.

**SSG is on by default for static routes.** A project with `src/pages` and a
`Router()` pre-renders every static route without any configuration. Static
means: no URL parameter, and no `rendering = "csr"` in the page.

Two ways to opt out, both without new syntax:

```python
# src/pages/dashboard.hyx — this page renders on the client only
rendering = "csr"

component Dashboard():
    ...
```

```json
// hydraconfig.json — the whole project, back to the old behaviour
{ "rendering": { "ssg": false } }
```

A **dynamic** route (`[slug]`) has no single page to build, so it is skipped and
named in the build log. That is deliberate, not a gap: SSR for dynamic routes
needs a server at request time, and the static build does not have one. The
four example projects still set `"ssg": false` — each is a single-page app
exercising the runtime, not a site with URLs a crawler would want, so
pre-rendering them would demonstrate the feature without exercising it.

If a project has `src/pages` but its `App` never calls `Router()`, nothing is
pre-rendered: with no router there is no route to pre-render, and the build says
so instead of writing empty pages.

### Data: `loader` and `action`

A page can have a **server half** in a file beside it — same name, `.server.hys`
instead of `.hyx`:

```
src/pages/blog/index.hyx           -> the page (client module: it renders in the browser)
src/pages/blog/index.server.hys    -> its loader and action (server module: never in the bundle)
```

```python
# src/pages/blog/index.server.hys
from "hydra/server" import env

export async def loader(event):
    return {"posts": await db.fetch_all(), "region": env("REGION", "local")}

export async def action(event):
    text = event.request.body.get("text")
    if not text:
        return {"ok": False, "reason": "empty"}
    await db.insert(text)
    return redirect("/blog?added=1")
```

```python
# src/pages/blog/index.hyx — the props ARE the loader's return value
component BlogIndex(posts: list = [], region: str = "?"):
    ...
```

`loader` runs **once per route at build time** (SSG), its result is rendered
into the HTML *and* inlined as JSON, so the client hydrates with the same values
instead of re-fetching. `action` runs when the same URL is `POST`ed.

**Why a separate file, and not `export def loader` inside the page.** A page
module is a client module: it renders in the browser and its imports end up in
the client bundle. A loader declared there could only be server-only *by
convention* — one stray `import fs` and the build breaks in a way that is hard to
read. A `.server.hys` is not reachable from the client at all, so the split is a
fact about the build rather than a rule to remember. It also means the client
bundle can never contain the loader even by accident.

`event` is one object, so the signature does not change when the framework adds a
field:

| field | is |
|---|---|
| `event.params` | dict of URL parameters (`{"slug": "hello"}`) |
| `event.url` | the path (`/blog`) |
| `event.query` | a `URLSearchParams`, so `.get("q")` |
| `event.request` | `method`, `headers`, `body` (an action only) |

A `.server.hys` with no page beside it is a **build error naming both files**,
because a loader nobody calls is almost always a typo in the filename.

Loaders **do** re-run on a client-side navigation now (0.8): a URL that was never
server-rendered fetches its data from `/__hydra/data`. See "SSR for dynamic
routes" below.

### SSR for dynamic routes

A route with a parameter has no single URL, so the static build cannot write one
file for it. `hydra dev`, `preview` and `serve` render those routes **per
request** from the same server bundle the build produces:

```
GET /blog/hello   ->  a full page, server-rendered, with the loader's data
GET /blog/world   ->  a full page with ITS data, not hello's
```

Two rules keep that honest, and both come from the runtime having one
module-global seed:

1. **Loading and rendering are separate calls**, and nothing may `await` between
   the render and `renderToString`. Otherwise two concurrent requests interleave
   and the second page renders with the first one's props.
2. **Identity is the full URL.** `/blog/a` and `/blog/b` match the same pattern,
   so the inlined payload carries `url` as well as `pattern`, and the client only
   trusts a payload for the URL it is rendering.

`GET /__hydra/data?url=/blog/hello` runs a loader on demand. That is what a
client-side navigation uses: the route was never server-rendered, so there is no
inlined payload, and the page fetches. A loader that throws is a `500` with its
message — never an empty data object, because "no items" and "the request
failed" look identical in a UI and mean different things.

**On a purely static deploy the endpoint does not exist.** The page then reports
`status: "error"` rather than pretending the data is empty; `use_loader` returns
`{data, status, error}` and a page that ignores it is unaffected.

### `hydra test`

```
hydra test                 # every *.test.hys under tests/, src/ or the root
hydra test path/to/x.test.hys
SNAP_UPDATE=1 hydra test   # accept snapshot changes
```

```python
# tests/card.test.hys
from "hydra/test" import test, expect, render, snapshot
from "../src/Card.hyx" import Card

def renders_the_title():
    expect(render(Card, {"title": "hi"})).to_contain("hi")

def the_whole_card():
    snapshot("card", render(Card, {"title": "s"}))

test("renders the title", renders_the_title)
test("the whole card", the_whole_card)
```

A `.test.hyx` may call `render(Card(title="hi"))` directly; in a `.hys` the props
go in a dict, because a `.hys` call with keyword arguments has no signature to
read for an imported component.

Each file is bundled with the same resolver and plugins the build uses and run
in **its own process**, so a global left behind by one file cannot affect the
next. A snapshot is written on first run and compared after that; a change is a
**failure**, not a silent rewrite.

### `hydra lsp`

```
hydra lsp        # JSON-RPC over stdio, LSP 3.17
```

What it does: `initialize`/`shutdown`/`exit` with real `Content-Length` framing,
`publishDiagnostics` from the **compiler's own** check (via `hydra check --json -`,
so the server cannot disagree with the build), hover, go-to-definition, and
rename within one file.

What it does **not** do, said plainly rather than implied: cross-file rename
(and it REFUSES a rename of an imported name, with the reason, instead of
half-doing it), completion, signature help, formatting, semantic tokens. An
unimplemented request gets `method not found` rather than silence.

### Incremental and parallel builds

Compiled modules are cached on disk under `.hydra/cache/`, keyed by
`sha256(source, compiler version, filename)`. Content-addressed, so a changed
file is a different key by construction, and a compiler upgrade is a miss rather
than a stale hit. A second build of an untouched project compiles nothing and
says so:

```
[hydra] compile cache: 8 reused, 0 compiled
```

`HYDRA_NO_CACHE=1`, or `"build": {"cache": false}`, turns it off.

**Parallel compilation is implemented, tested, and off below scale — because it
was measured.** `benchmarks/compile.mjs` on a 2-vCPU box, 120 files:

| | time |
|---|---|
| serial, cold | 47 ms (0.39 ms/file) |
| cache, cold | 91 ms (first run; it writes) |
| cache, warm | 1 ms (120/120 hits) |
| worker pool | 124 ms |

The compiler is fast enough per file that a `worker_threads` pool spends more on
startup and a second copy of the addon than it saves. `shouldPool` is that
measured threshold, so the pool runs on a project large enough for it to pay
(roughly 5,000 files at this speed) and is a no-op otherwise.

Build output: `dist/index.html`, `dist/assets/index-<hash>.js`, `dist/assets/index.css`,
plus chunks for dynamic `import()`.

## Configuration

A single optional `hydraconfig.json` in the project root:

```json
{
  "name": "production-app",
  "root": "./src",
  "outputDir": "./dist",
  "base": "/",
  "server": {
    "port": 5173,
    "host": "127.0.0.1",
    "proxy": { "/api": "http://127.0.0.1:8000" }
  },
  "compiler": {
    "target": "react-18",
    "strict": true
  },
  "rendering": { "ssg": true },
  "styling": { "tailwind": true },
  "tailwind": {
    "theme": {
      "extend": {
        "colors": { "primary": "#f54e00" }
      }
    }
  }
}
```

`base` also handles subpath deployment: with `"/sub/"`, HTML, chunks and assets
all reference `/sub/`, and `hydra preview` serves them there. `server.proxy`
forwards during dev and preview, keeping the prefix intact.

Environment variables: `HYDRA_NATIVE` (addon path), `HYDRA_COMPILER` (CLI path),
`HYDRA_RUNNER` (runner path), `HYDRA_RUNTIME_PATH` (what `hydra` resolves to).

## CLI reference

```
hydra <file.hyx>             compile to stdout
hydra <file.hys> -o out.mjs  compile to a file
hydra --check <file.hyx>     parse only; exit 1 on error
hydra check [files]          parse + warn (unbound names, unknown members)
hydra types [files]          write <file>.hyx.d.ts for TypeScript
hydra --json <file.hyx>      emit {code, map}
hydra --stdin [filename]     read from stdin

hydra repl                   interactive REPL

```

Run `hydra doctor` first when a build misbehaves — it reports node, npm, bun,
config discovery and source counts. `hydra watch` writes to `watch-out/`,
mirroring `src/`, never next to the sources it reads.

### Using HydraScript from TypeScript

`.hyx` modules are visible to TypeScript, so a mixed project type-checks across
the boundary. Generate the declarations once, and again whenever a component's
parameters change:

```bash
npx hydra types        # writes src/Widget.hyx.d.ts next to src/Widget.hyx
```

The filename is the contract: TypeScript looks for `<file>.hyx.d.ts` beside
`<file>.hyx`. A sibling `Widget.d.ts` is ignored.

```tsx
import { Widget } from './Widget.hyx'

// `label` is a string and `size` is an optional number, straight from the
// component's own parameters. A typo is an error, not a silent `any`:
<Widget label="hi" size={2} />
```

Rules the generator follows, because a declaration that lies is worse than none:

- Prop types come from the component's parameters, mapped from Python names
  (`int`/`float` -> `number`, `str` -> `string`, `list` -> `any[]`). An
  unannotated parameter becomes `any`, never a guess.
- A construct it cannot represent is omitted rather than approximated: a class
  gets a permissive index signature, not invented members.
- A module with no exports produces no file, so a hand-written `.d.ts` is never
  clobbered.

A `declare module '*.hyx'` shim is the tempting five-minute alternative. It makes
every import `any` and silently switches off type checking at exactly the
boundary you wanted checked, so prefer `hydra types`.

## Installation

```bash
# As a dev dependency in a project
npm install -D hydrascript

# Or globally, to get the `hydra` command anywhere
npm install -g hydrascript

# Run it once without installing
npx hydrascript init myapp
```

The package is on the npm registry; the names differ, and that is deliberate.
The **package** is `hydrascript`, the **command** is `hydra`. So `npx hydrascript`
installs the package and runs the `hydra` binary inside it. There is an unrelated
package already called `hydra` on the registry, so `npx hydra` without a local
install would fetch that one instead — always go through `hydrascript`.

To pin a specific commit instead of the released version:

```bash
npm install -D hydrascript@github:hanxthvy/hydrascript#<sha>
```

The npm package ships prebuilt binaries for Linux x86_64 only. On macOS, Windows
or ARM, build from source:

```bash
git clone https://github.com/hanxthvy/hydrascript.git
cd hydrascript/compiler-rs
cargo build --release
cp target/release/hydra ../bin/hydra
cp target/release/libhydra.so ../bin/hydra.node
```

Requirements: Node 22+ (`engines` enforces it; the runner uses the global
`WebSocket`), Rust 1.75+ (edition 2021) to build the compiler.
`npm install` brings esbuild, PostCSS, Tailwind and Autoprefixer, which the
runner loads from the project's own `node_modules`.

## Permanent limitations

Design decisions that will not change. Each one is a choice, and the reason is
here so it can be argued with rather than guessed at.

- **No multiple inheritance.** A second base would have to be emulated, and every
  emulation differs from Python somewhere the author cannot see: which base wins
  in a diamond, whether `super()` follows the MRO, what `isinstance(x, Both)`
  answers. Refused by name at parse time, on both targets.
- **Keyword arguments only where a signature can be read.** A function defined in
  the file, a function imported from a RELATIVE `.hys`/`.hyx` file, and a method
  whose name only one class in the file declares. A call into a package has no
  source to read; a method whose name two classes declare needs the receiver's
  type, which is not tracked. Both are compile errors, never silent miscompiles.
- **Builtins with no exact JS equivalent keep their differences, stated not
  hidden.** `any` / `all` short-circuit and answer the empty-sequence cases the
  way Python does (`any([])` is `False`, `all([])` is `True`). `getattr(x, "y")`
  with no default raises `AttributeError` rather than returning `undefined`,
  which is what makes the three-argument form mean anything. `repr` is JSON for
  plain data and `String(x)` elsewhere, because a JS object has no `__repr__`.
- **Prebuilt binary is Linux x86_64 only, and needs glibc 2.35+.** macOS,
  Windows and ARM build the compiler from source; the npm package says so and CI
  has never published a binary it did not build for that target. The glibc floor
  is Ubuntu 22.04, because that is the runner the release is built on: a binary
  linked against a newer glibc refuses to *start* on an older system, which is
  how 0.7.0 shipped a tarball whose `hydra build` worked (it runs the Node
  runner) while `hydra run` and `hydra check` died with "weak version
  `GLIBC_2.39' not found". The release workflow now fails if the binary requires
  a glibc newer than the runner it was built on.
- **Rounding is Python's, to the tie.** `format(1.5, ".0f")` is `2` and
  `format(0.5, ".0f")` is `0`: ties go to the even digit, judged against the
  value's exact binary expansion. `toFixed` rounds ties away from zero, which is
  a different answer on money and percentages, so it is not used for a
  `f`/`F`/`e`/`E` spec. The tie is detected after expanding the double to 100
  fraction digits; beyond `1e-100` the difference is under any precision an
  f-string can express, which is a bound rather than a guess.

## Roadmap

What is coming, and what is deliberately not. Nothing here is a promise about
dates; the version numbers are targets and the order is the honest part.

| Target | Item | State |
|---|---|---|
| 0.6.2 | File-based routing, per-route SSG | shipped |
| 0.6.2 | `hydra routes`, route table printed and generated | shipped |
| 0.6.2 | Keyword arguments across files and for methods | shipped |
| 0.7 | Live reload: websocket push, in-browser error overlay | shipped |
| 0.7 | `loader` / `action` (`.server.hys` beside a page) | shipped |
| 0.7 | `hydra/server` and `hydra/client`, enforced per module | shipped |
| 0.7 | SSG by default for static routes, `rendering = "csr"` opt-out | shipped |
| 0.8 | SSR for dynamic routes, rendered per request | shipped |
| 0.8 | Loaders re-run on a client-side navigation | shipped |
| 0.9 | `hydra-lsp`: diagnostics, hover, go-to-definition, rename | shipped |
| 0.9 | `hydra test`: component, route and snapshot tests | shipped |
| 1.0 | Incremental compile cache (content-addressed, on disk) | shipped |
| 1.0 | Parallel compilation (worker pool, measured, off below scale) | shipped |
| next | React Fast Refresh (state preserved across an edit) | not started |
| next | Cross-file rename in `hydra-lsp` | not started |
| next | Completion and signature help in `hydra-lsp` | not started |

The three "next" rows are the honest remainder, and each is a feature with its
own correctness argument rather than a gap:

- **Fast Refresh** needs a module boundary the compiler can prove (which
  components can be swapped without losing state, which cannot). Live reload
  ships; calling it Fast Refresh would be wrong, so it is not.
- **Cross-file rename** needs the import graph resolved for the rename target.
  `hydra-lsp` refuses a rename it cannot complete, with the reason, rather than
  half-renaming a name that is imported.
- **Completion** needs the compiler's scope information exposed per position,
  which is the same work as a real symbol table. Until then the LSP answers
  "method not found" rather than offering guesses.

Not planned, and not a gap: React Server Components, islands, streaming SSR and
multi-platform deploy adapters. The compiler's output is ordinary React on the
client, and that is a feature with a name rather than an unfinished one.
