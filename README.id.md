## Ini apa

HydraScript mengompilasi berkas `.hyx` berbasis indentasi menjadi React TSX, dan
berkas `.hys` menjadi JavaScript biasa. Compiler-nya biner Rust; runner Node
kecil membungkus esbuild, PostCSS dan Tailwind untuk menghasilkan situs.

**Status: 0.11.1, pra-1.0.** Compiler, file-based router, prerender, server
rendering, language server, dan test runner sudah jadi dan ditutup 311 tes Rust
serta 146 tes Node di 20 suite. Sintaks bahasanya dibekukan (lihat di bawah); yang
dirilis sampai 1.0 adalah perkakas, bukan konstruksi baru.

Batas yang diketahui, ditulis terang-terangan: Fast Refresh mempertahankan state
komponen yang sudah ter-mount saat kamu mengedit, tapi markup hasil editnya belum
ikut berganti di pohon yang hidup. Sampai itu selesai, `hydra dev` mengatakannya
apa adanya — lihat [Roadmap](#roadmap).

### Sintaksnya dibekukan di 0.3

Tidak ada fitur bahasa baru yang direncanakan sampai 1.0. Ini keputusan, bukan
kelambanan: bahasa kecil dipercaya dengan berdiri diam cukup lama sampai orang
mau membangun di atasnya, dan setiap tambahan sintaks adalah jalur emitter yang
harus dijaga seumur hidup. Yang berubah antara sekarang dan 1.0 adalah pipa
ledeng, bukan bahasanya: build, dev server, diagnosa, integrasi bundler, CI, dan
deklarasi tipe. Kalau sebuah ide butuh sintaks baru, jawabannya hampir selalu
tidak.

Perubahan yang merusak tetap terjadi, dan setiap yang merusak wajib membawa
codemod atau catatan migrasi. Tidak ada pengecualian, walaupun penggunanya cuma
sedikit: proyek mati bukan karena fiturnya kurang, tapi karena orang berhenti
berani naik versi.

## Contoh 30 detik

```python
# [xihanzu-NR]
from hydra import state

component Counter(start: int = 0):
    count, set_count = state(start)

    div(className="counter"):
        h2: f"Value: {count}"
        button(onClick=lambda: set_count(count + 1)): "Add"
```

menjadi (keluaran compiler verbatim, footer source-map base64 dipangkas):

```tsx
// [xihanzu-NR]
// GENERATED by hydra — edit the .hsx file, not this one
import { state } from 'hydra';

export function Counter({ start = 0 }: CounterProps) {
  let [count, set_count] = state(start);
  return (
    <div className="counter">
      <h2>{`Value: ${count}`}</h2>
      <button onClick={(() => set_count((count + 1)))}>Add</button>
    </div>
  );
}

export interface CounterProps {
  start?: number;
}
```

Tanpa virtual machine, tanpa interpreter: keluarannya React biasa. Satu-satunya
hal khas HydraScript di situ adalah impor `hydra`, dan impor itu hanya muncul
kalau berkasnya benar-benar memanggil helper.

## Perbandingan jujur dengan TSX

HydraScript lebih pendek untuk hal-hal yang bikin JSX bertele-tele, dan tidak
lebih baik maupun lebih buruk untuk sisanya. Ini bentuk nyata dari tukarannya:

| Bidang | TSX | HydraScript | Diverifikasi bagaimana |
|---|---|---|---|
| Sarang elemen | Tag penutup | Indentasi | Baca keluaran TSX-nya |
| UI banyak cabang | Ternary bersarang / IIFE switch | `if / elif / else`, `match` | Dikompilasi keduanya |
| Kelas dinamis | impor `clsx(...)` | dict `cls={...}`, tanpa impor | Menghasilkan `cx(...)` |
| prevent/stop event | `e.preventDefault()` manual | `on_submit_prevent_stop=fn` | Menghasilkan kedua panggilan |
| Render daftar | `.map()` + `key` | `for x in xs:` + `key=` | Menghasilkan `.map()` |
| Interpolasi string | Template literal | f-string | Menghasilkan template literal |
| State | `const [v, setV] = useState()` | `v, set_v = state()` | Menghasilkan `useState` |
| Banyak root | `<>...</>` manual | Otomatis | Menghasilkan fragment |
| Jumlah token, komponen yang sama | 188 token | 130 token | `benchmarks/tokens.py` |

Baris terakhir diukur pada satu komponen di repo ini, bukan korpus — lihat
bagian berikutnya untuk tahu persis apa yang diklaim dan tidak.

Satu koreksi yang layak disebut karena sering mengejutkan: `count && <Badge/>`
mencetak `0`, bukan tidak ada apa-apa. Compiler menghasilkan
`count && (<span>…)` persis seperti TSX. Pakai `if count:` kalau mau penjagaan.

## Referensi sintaks

### Indentasi

`h1: "teks"` menaruh satu anak secara inline. Tanda `:` dengan blok menjorok
membuat sarang:

```python
div(className="container"):
    header(className="header"):
        h1: "System Status"
        p: "All telemetry nodes online."
```

### Banyak root

Saudara di puncak komponen otomatis dibungkus fragment:

```python
component MetricPair(label: str, value: str):
    span(className="label"): label
    span(className="value"): value
```

```tsx
export function MetricPair({ label, value }: MetricPairProps) {
  return (
  <>
    <span className="label">{label}</span>
    <span className="value">{value}</span>
  </>
  );
}
```

### Prop dan event

`class` / `cls` → `className`, `for` → `htmlFor`, `tab_index` → `tabIndex`,
`on_click` → `onClick`, `on_change` → `onChange`, `on_submit` → `onSubmit`,
`on_key_down` → `onKeyDown`. `aria_*` dan `data_*` tetap pakai tanda hubung.

Sufiks menambahkan boilerplate-nya:

* `on_submit_prevent=fn` → `e.preventDefault()` lalu `fn(e)`
* `on_click_stop=fn` → `e.stopPropagation()` lalu `fn(e)`
* `on_click_prevent_stop=fn` → keduanya

### Kelas dinamis

```python
div(cls={"btn": True, "active": is_active, "muted": not is_active}): "Hi"
```

menghasilkan `className={cx({...})}` dengan `cx` diimpor dari `hydra`.

## Fitur bahasa

Semantik Python dipertahankan, bukan didekati. Semua ini punya tesnya di
`compiler-rs/tests/compile.rs`:

```python
a = 0 < x < 10              # perbandingan berantai
found = key in items        # keanggotaan, bukan keberadaan properti
same = a is b               # identitas
a, b = b, a                 # penugasan paralel
p = q = r = 0               # penugasan berantai
name, age = get_user()      # destructuring
xs[1:3] / xs[:5] / xs[::2]  # slicing
{k: v for k, v in pairs}    # dict comprehension, target tuple juga
{x for x in xs}             # set comprehension
total = 0
for x in xs:
    total += x              # augmented assignment ke target apa pun
```

`def` berisi `yield` menjadi generator (`function*`). `class` dengan `__init__`
menjadi kelas ES (`this`, `@staticmethod`, pewarisan). `@deco` menjadi
`f = deco(f)`. `@dataclass` menyintesis `__init__` dari field beranotasi.

`slot` di badan komponen merender `props.children` dan menambahkan `children`
ke tipe props-nya:

```python
component Card(title: str):
    div(className="card"):
        h3: title
        slot
```

### Tipe error

`class MyError(Exception)` menghasilkan kelas JS sungguhan, dan `raise` menjaga
stack trace tetap berguna:

```python
class ValidationError(Exception):
    pass

def check(x):
    if x < 0:
        raise ValidationError("negative")
```

### Sisi `.hys`

Berkas `.hys` dikompilasi ke JavaScript biasa — tanpa React, tanpa JSX. Berguna
untuk skrip dan utilitas Node:

```python
from "node:fs/promises" import readFile

async def count_lines(path: str):
    raw = await readFile(path, "utf8")
    return len(raw.split("\n"))
```

Jalankan langsung dengan `hydra run script.hys`.

## Runtime (`hydra`)

Helper compiler maupun adapter React datang dari satu specifier, `hydra`, yang
mengarah ke `runtime/hydra.ts`.

**Tiga specifier, dan compiler menegakkan mana yang boleh dipakai di mana:**

| import dari | berisi | boleh di |
|---|---|---|
| `hydra` | helper universal (`state`, `fetch_json`, `mount`, `Router`) | modul apa saja |
| `hydra/server` | `env`, `read_text`, `write_text`, `redirect` | hanya `.server.hys` |
| `hydra/client` | `window_size`, `scroll_to`, `local_storage`, `clipboard` | hanya `.hyx`/`.tsx` |

Mengimpor `hydra/server` dari halaman adalah **error build yang menyebut berkasnya
dan alasannya**, bukan stack trace saat runtime. Kebalikannya juga diperiksa:
`hydra/client` di `.server.hys` gagal, karena di sana tidak ada `window`. Compiler
menolak import yang bisa ia buktikan salah, dan hanya itu jenis import yang ia tolak.

| Fungsi | API React |
|---|---|
| `v, set_v = state(init)` | `useState` |
| `r = ref(init)` | `useRef` |
| `cb = callback(fn, deps)` | `useCallback` |
| `effect(fn, deps)` | `useEffect` |
| `v, toggle_fn, set_v = toggle(False)` | kustom (3-tuple, bukan 2) |
| `is_mounted = use_mounted()` | kustom |

Runtime juga mengekspor ~150 helper kecil (`debounce`, `fetch_json`, `cx`,
`get_path`, `use_dark_mode`, …). `hydra doctor` dan `hydra list` cara tercepat
melihat apa yang nyata-nyata dimiliki sebuah proyek.

**Jangan menamai berkas runtime-mu sendiri `src/hydra.hys`.** Specifier `hydra`
adalah kontrak compiler; berkas proyek tidak bisa memenuhi semua helper yang
bisa dihasilkan compiler, dan menutupinya gagal dengan `No matching export in
src/hydra.hys for import len_of`. Impor kode proyek lewat jalur relatif.

## Fungsi bawaan

Ini tidak perlu impor:

| HydraScript | Menghasilkan |
|---|---|
| `len(xs)` / `len(d)` | `xs.length` / `len_of(d)` sadar-dict |
| `max(a, b)` / `max(xs)` | `Math.max(a, b)` / runtime `max_of(xs)` |
| `min(a, b)` / `min(xs)` | `Math.min(a, b)` / runtime `min_of(xs)` |
| `abs(x)` / `round(x)` | `Math.abs` / runtime `round_py(x)` — tie ke angka genap |
| `pow(a, b)` | `a ** b` |
| `sum(xs)` / `sum(xs, start)` | reduce / helper runtime |
| `sorted(xs)` / `reversed(xs)` | tidak memutasi; angka dibandingkan sebagai angka |
| `str` / `int` / `float` / `bool` | `String` / runtime `int` / `float` / `truthy` |
| `isinstance(x, int)` | `isinstance(x, Number)` |
| `type(x).__name__` | `x.constructor.name` |
| `enumerate` / `range` / `zip` | helper runtime, diimpor otomatis |
| `xs.some(lambda x: x > 2)` | `xs.some((x) => x > 2)` |
| `print(x)` | `console.log(x)` |
| `assert cond, "msg"` | `assert_(cond, "msg")` — melempar |
| `raise ValueError("x")` | `raise_(new ValueError("x"))` |

Method string Python tanpa padanan JS (`s.capitalize()`, `s.zfill(4)`,
`s.isdigit()`) dan helper koleksi (`", ".join(xs)`, `d.get(k, v)`,
`xs.extend(ys)`) memanggil runtime. Impornya disuntikkan otomatis. Helper
mendelegasikan ke receiver yang punya method setara, jadi `.add()` / `.remove()`
tetap aman pada objek bukan-list seperti `DOMTokenList`.

### Konstruktor

Python tidak punya `new`; API browser butuh, jadi ini bagian dari bahasa:

```python
def setup():
    obs = new IntersectionObserver(on_change, {"threshold": 0.25})
    obs.observe(el)
    return obs
```

`fn?.(x)` dikompilasi jadi panggilan opsional.

### Impor modul

```python
from "react" import useState, useEffect   # impor bernama
from "./Header.hyx" import Header         # komponen lokal
import "./index.css"                      # efek samping
from "./logo.svg" import logo             # aset: default import

    button: label
export def tax(amount):                   # fungsi diekspor

```

## Komponen dan keluaran JSX

`component` menjadi fungsi komponen React yang diekspor dengan interface `Props`
yang cocok. Default prop menjadi default destructuring. `self` adalah `this`,
`__init__` adalah konstruktor, dan `super().__init__(x)` menjadi `super(x)`.

Validasi keluaran: setiap emit diperiksa sebelum keluar dari compiler
(`src/validate.rs`). Yang ditolak adalah bentuk yang selalu JavaScript tidak
valid — deklarasi yang target-nya member expression, `new` tanpa yang
dikonstruksi, kurung tidak seimbang di keluaran JS biasa. Kegagalan di sini
adalah bug compiler dan pesannya menyatakan itu. Ini ada karena dulu compiler
pernah melaporkan sukses untuk keluaran yang tidak diterima mesin JS mana pun.

## Meta-framework

**`hydra dev`, `build` dan `preview` memakai esbuild, bukan Vite.** PostCSS,
Autoprefixer dan Tailwind digerakkan secara programatik, jadi proyek tidak
membutuhkan `vite.config.ts`, `tailwind.config.ts` maupun `postcss.config.js`.

| Perintah | Fungsi |
|---|---|
| `hydra dev` | Build, sajikan, dan build ulang saat berkas berubah |
| `hydra build` | Build produksi: aset ber-hash, CSS terminifikasi, SSG |
| `hydra preview` | Menyajikan `dist/` (build dulu kalau belum ada) |
| `hydra serve` / `hydra start` | Menyajikan hasil build untuk deploy; menolak start kalau separuh server tidak ada |
| `hydra run <file.hys>` | Menjalankan skrip in-process |

Artefak, header respons, kompresi, dan batas platform ada di
[`docs/DEPLOYING.md`](docs/DEPLOYING.md).

**Soal "HMR":** `hydra dev` memantau `src/`, build ulang, dan **memuat ulang
halaman di browser lewat websocket** — tanpa dependensi, tanpa ekstensi, sekitar
**~190 ms** dari simpan ke reload, median 3 edit (`node benchmarks/dev-reload.mjs`); build pertama ~1,4 detik. Yang *tidak* ia lakukan adalah mempertahankan
state komponen melintasi perubahan: edit yang berhasil memuat ulang halaman, bukan
menukar modul di tempat. Menyebutnya React Fast Refresh akan salah, jadi README
ini menyebutnya live reload.

**Build ulang yang gagal tidak memuat ulang.** Error-nya dikirim ke halaman,
jadi console menampilkan pesan compiler beserta berkas dan barisnya, dan kamu
tetap memegang halaman terakhir yang bekerja sampai kodenya bisa dikompilasi lagi.

### Routing berbasis berkas

`src/pages/` adalah tabel route-nya. Nama berkas menentukan URL-nya, dan
`hydra routes` mencetak hasilnya supaya tidak ada yang tersembunyi.

```
src/pages/index.hyx             -> /
src/pages/about.hyx             -> /about
src/pages/blog/index.hyx        -> /blog
src/pages/blog/[slug].hyx       -> /blog/:slug
src/pages/docs/[...rest].hyx    -> /docs/*      (satu segmen atau lebih)
src/pages/files/[[...rest]].hyx -> /files/*     (boleh juga /files)
src/pages/(marketing)/price.hyx -> /price       (grup: hanya untuk layout)
src/pages/_partials/Hero.hyx    -> tidak routable
```

`_layout.hyx` membungkus semua route di foldernya ke bawah, `_404.hyx` dipakai
saat tidak ada yang cocok, dan `_error.hyx` jadi batas error untuk foldernya.
Ketiganya boleh ada di banyak level; yang terdekat menang.

Dua berkas yang mengklaim URL yang sama adalah **error build** yang menyebut
kedua berkasnya, bukan pertandingan yang diputuskan diam-diam. Itu berlaku untuk
`blog/[slug].hyx` + `blog/[id].hyx` (satu posisi URL, dua nama parameter) dan
untuk `about.hyx` + `about/index.hyx` (satu URL, dua berkas).

Direktori route bisa diubah lewat `"routes"` di `hydraconfig.json`, atau
dimatikan dengan `"routes": false`.

### SSG per route

**SSG menulis satu berkas HTML per route statis**: `dist/about/index.html`, bukan
satu `dist/index.html` untuk seluruh situs. Route dinamis dilewati dan
**disebutkan namanya** di log build, karena URL ber-parameter tidak punya satu
halaman untuk dibangun:

```
[hydra] 4 route(s) from src/pages, 1 dynamic (/blog/:slug)
[hydra] SSG: pre-rendered 3/3 static route(s) into dist/
[hydra] SSG: 1 dynamic route(s) left as the client shell (/blog/:slug) —
        a URL with a parameter has no single page to build
```

Runtime gate sekarang memeriksa **setiap** `index.html` yang dihasilkan, bukan
hanya yang di akar: dengan HTML per-route, memeriksa satu halaman meninggalkan
setiap route lain tanpa pemeriksaan.

**SSG menyala secara default untuk route statis.** Proyek dengan `src/pages` dan
`Router()` pra-render setiap route statis tanpa konfigurasi apa pun. Statis
artinya: tanpa parameter URL, dan tanpa `rendering = "csr"` di halamannya.

Dua cara opt-out, keduanya tanpa sintaks baru:

```python
# src/pages/dashboard.hyx — halaman ini render di klien saja
rendering = "csr"

component Dashboard():
    ...
```

```json
// hydraconfig.json — seluruh proyek, kembali ke perilaku lama
{ "rendering": { "ssg": false } }
```

Route **dinamis** (`[slug]`) tidak punya satu halaman untuk dibangun, jadi ia
dilewati dan disebut namanya di log build. Itu sengaja, bukan celah: SSR untuk
route dinamis butuh server saat request, dan build statis tidak punya itu. Empat
proyek contoh masih memakai `"ssg": false` — masing-masing adalah satu-halaman
yang menguji runtime, bukan situs dengan URL yang diinginkan crawler.

Kalau proyek punya `src/pages` tapi `App`-nya tidak pernah memanggil `Router()`,
tidak ada yang dipra-render: tanpa router tidak ada route untuk dipra-render, dan
build mengatakannya, bukan menulis halaman kosong.

### Metadata: `meta`

Sebuah halaman boleh mendeklarasikan `<title>` dan deskripsinya sendiri sebagai
dict di level modul:

```python
# src/pages/about.hyx
meta = {"title": "About — Hanz", "description": "Siapa yang menulis ini."}

component About():
    ...
```

Nilai itu dipakai di dua tempat, dari satu sumber:

- **Saat build**, ke HTML statis route itu: `dist/about/index.html` memuat
  `<title>` dan `<meta name="description">` tersebut, menggantikan punya cangkang.
  Halaman tanpa `meta` tetap memakai judul cangkang, begitu juga setiap route yang
  tidak pernah diberi `meta`.
- **Saat navigasi klien**, oleh `Router()` — yang sudah dirender setiap proyek
  ber-route. Pindah dari `/` ke `/about` memasang judul baru; kembali lagi
  memulihkan judul cangkang, karena halaman yang tidak mengklaim apa pun tidak
  boleh mewarisi judul halaman sebelumnya.

Dua kunci, `title` dan `description`. Kunci ketiga adalah **error build yang
menyebut namanya**, bukan nilai yang tidak pernah sampai ke halaman: ini bukan
head manager, dan tidak akan tumbuh jadi satu. Ini juga bukan hook — tidak ada
`use_head`, dan menambahkannya berarti dua cara mengatakan hal yang sama.

`meta` dibaca dari SUMBER halaman, di tempat yang sama `rendering = "csr"` dibaca,
bukan dengan mengimpor halaman. Compiler meng-emit `meta` level modul sebagai
`const` lokal, bukan ekspor, jadi impor tidak akan membawanya — dan halaman adalah
modul klien, jadi mengimpornya saat build berarti menjalankan impor-impornya di
node, melewati batas yang justru dijaga `.server.hys`.

**Yang sengaja belum:** metadata yang bergantung pada URL (`/blog/hello` ingin
"hello" di judulnya) bukan metadata statis, dan ini tidak berpura-pura sebaliknya
— cangkang route dinamis memakai judul aplikasi, dan klien memasang judul
halamannya setelah hidrasi. Tidak ada open-graph, twitter card, canonical, atau
structured data; masing-masing adalah klaim terpisah tentang sebuah halaman dan
butuh pernyataannya sendiri tentang apa yang membuatnya benar.

### Data: `loader` dan `action`

Sebuah halaman bisa punya **belahan server** di berkas di sampingnya — nama sama,
`.server.hys` bukan `.hyx`:

```
src/pages/blog/index.hyx           -> halamannya (modul klien: render di browser)
src/pages/blog/index.server.hys    -> loader dan action-nya (modul server: tak pernah masuk bundel)
```

```python
# src/pages/blog/index.server.hys
from "hydra/server" import env

export async def loader(event):
    return {"posts": await db.fetch_all(), "region": env("REGION", "local")}

export async def action(event):
    text = event.request.body.get("text")
    if not text:
        return {"ok": False, "reason": "empty"}
    await db.insert(text)
    return redirect("/blog?added=1")
```

```python
# src/pages/blog/index.hyx — props-nya ADALAH nilai balikan loader
component BlogIndex(posts: list = [], region: str = "?"):
    ...
```

`loader` jalan **sekali per route saat build** (SSG), hasilnya dirender ke HTML
*dan* di-inline sebagai JSON, jadi klien hydrate dengan nilai yang sama alih-alih
fetch ulang. `action` jalan saat URL yang sama di-`POST`.

**Kenapa berkas terpisah, bukan `export def loader` di dalam halaman.** Modul
halaman adalah modul klien: ia render di browser dan import-nya masuk bundel
klien. Loader yang dideklarasikan di sana hanya bisa server-only *berdasarkan
konvensi* — satu `import fs` nyasar dan build rusak dengan cara yang sulit dibaca.
`.server.hys` sama sekali tidak terjangkau dari klien, jadi pemisahannya fakta
tentang build, bukan aturan yang harus diingat.

`event` adalah satu objek, jadi tanda tangannya tidak berubah saat framework
menambah field: `event.params`, `event.url`, `event.query` (punya `.get()`), dan
`event.request` (`method`, `headers`, `body`, hanya untuk action).

`.server.hys` tanpa halaman di sampingnya adalah **error build yang menyebut
kedua berkasnya**, karena loader yang tak pernah dipanggil hampir selalu salah
nama berkas.

**Belum selesai:** loader tidak jalan ulang saat navigasi *sisi klien* — JSON
yang di-inline itulah yang klien punya sampai halaman dimuat ulang. Itu, dan SSR
untuk route dinamis, adalah bagian berikutnya; lihat roadmap.

Keluaran build: `dist/index.html`, `dist/assets/index-<hash>.js`,
`dist/assets/index.css`, plus chunk untuk `import()` dinamis.

## Instalasi

### Memakai HydraScript dari TypeScript

Modul `.hyx` bisa dilihat TypeScript, jadi proyek campuran ikut ter-cek lintas
batas. Jalankan sekali, dan ulangi setiap parameter komponen berubah:

```bash
npx hydra types        # menulis src/Widget.hyx.d.ts di samping src/Widget.hyx
```

Nama berkasnya itu kontraknya: TypeScript mencari `<file>.hyx.d.ts` di samping
`<file>.hyx`. `Widget.d.ts` di folder yang sama akan diabaikan.

Aturan yang dipegang generator, karena deklarasi yang bohong lebih buruk daripada
tidak ada:

- Tipe prop diambil dari parameter komponen, dipetakan dari nama Python
  (`int`/`float` -> `number`, `str` -> `string`, `list` -> `any[]`). Parameter
  tanpa anotasi jadi `any`, bukan tebakan.
- Yang tidak bisa diwakili dihilangkan, bukan dikira-kira: kelas dapat index
  signature yang permisif, bukan member karangan.
- Modul tanpa export tidak menghasilkan berkas, jadi `.d.ts` tulisan tangan tidak
  pernah tertimpa.

Shim `declare module '*.hyx'` itu alternatif lima menit yang menggoda. Dia membuat
semua impor jadi `any` dan diam-diam mematikan pengecekan tipe tepat di batas yang
ingin kamu cek, jadi lebih baik pakai `hydra types`.

```bash
# Sebagai dev dependency di proyek
npm install -D hydrascript

# Atau global, supaya perintah `hydra` ada di mana saja
npm install -g hydrascript

# Jalankan sekali tanpa memasang
npx hydrascript init myapp
```

Paketnya ada di registry npm, dan nama paket berbeda dari nama perintah, itu
sengaja. **Paketnya** `hydrascript`, **perintahnya** `hydra`. Jadi `npx hydrascript`
memasang paketnya lalu menjalankan biner `hydra` di dalamnya. Di registry sudah ada
paket lain bernama `hydra`, jadi `npx hydra` tanpa pemasangan lokal akan mengambil
paket itu — selalu lewat `hydrascript`.

Untuk mengunci commit tertentu alih-alih versi rilis:

```bash
npm install -D hydrascript@github:hanxthvy/hydrascript#<sha>
```

Paket npm mengirim biner prabangun hanya untuk Linux x86_64. Di macOS, Windows
atau ARM, bangun dari sumber:

```bash
git clone https://github.com/hanxthvy/hydrascript.git
cd hydrascript/compiler-rs
cargo build --release
cp target/release/hydra ../bin/hydra
cp target/release/libhydra.so ../bin/hydra.node
```

Kebutuhan: Node 22+ (`engines` menegakkannya; runner memakai `WebSocket`
global), Rust 1.75+ (edisi 2021) untuk membangun compiler.
`npm install` membawa esbuild, PostCSS, Tailwind dan Autoprefixer, yang dimuat
runner dari `node_modules` proyek itu sendiri.

## Keterbatasan permanen

Keputusan desain yang tidak akan berubah. Semuanya pilihan, dan alasannya ditulis
di sini biar bisa dibantah, bukan ditebak.

- **Tidak ada multiple inheritance.** Base kedua harus diemulasi, dan tiap
  emulasi berbeda dari Python di tempat yang tidak bisa dilihat penulisnya: base
  mana yang menang di diamond, apakah `super()` mengikuti MRO, apa jawaban
  `isinstance(x, Both)`. Ditolak dengan menyebut namanya saat parse, di kedua
  target.
- **Argumen kata kunci hanya di mana signature-nya bisa dibaca.** Fungsi di
  berkas yang sama, fungsi dari impor relatif `.hys`/`.hyx`, dan metode yang
  namanya cuma dideklarasikan satu kelas di berkas itu. Panggilan ke paket tidak
  punya sumber untuk dibaca; metode yang namanya dideklarasikan dua kelas
  butuh tipe receiver, dan itu tidak dilacak. Keduanya error kompilasi, bukan
  salah-kompilasi diam-diam.
- **Builtin tanpa padanan JS persis menyimpan bedanya, dan bedanya disebut.**
  `any` / `all` short-circuit dan menjawab kasus urutan kosong seperti Python
  (`any([])` = `False`, `all([])` = `True`). `getattr(x, "y")` tanpa default
  melempar `AttributeError`, bukan mengembalikan `undefined` — itulah yang bikin
  bentuk tiga-argumen punya arti. `repr` adalah JSON untuk data biasa dan
  `String(x)` untuk sisanya, karena objek JS tidak punya `__repr__`.
- **Biner prabangun hanya Linux x86_64.** macOS, Windows dan ARM membangun
  compiler dari sumber; paket npm-nya bilang begitu, dan CI tidak pernah
  menerbitkan biner yang tidak dibangun untuk target itu.
- **Pembulatan mengikuti Python, sampai ke tie-nya.** `format(1.5, ".0f")` = `2`
  dan `format(0.5, ".0f")` = `0`: tie ke digit genap, dinilai terhadap ekspansi
  biner eksak. `toFixed` membulatkan tie menjauh dari nol, jawaban berbeda untuk
  uang dan persentase, jadi tidak dipakai untuk spec `f`/`F`/`e`/`E`. Tie-nya
  dideteksi setelah double diekspansi ke 100 digit pecahan; di luar `1e-100`
  bedanya di bawah presisi apa pun yang bisa dinyatakan f-string, dan itu batas
  yang disebut, bukan tebakan.

### Fast Refresh, tepatnya

State **memang** dipertahankan saat kamu mengedit komponen: dev server mengirim
`refresh` alih-alih `reload`, boundary di `runtime/hydra.ts` menjaga identitas
fungsi komponen, dan pohon yang sudah ter-mount mempertahankan hook-nya. Itu
terukur — `scripts/fast-refresh-probe.mjs` menggerakkan browser sungguhan,
mengklik counter sampai 3, mengedit komponennya, lalu membaca 3 lagi dengan
`window` halaman tetap utuh.

Yang **belum** selesai adalah bagian keduanya: markup baru tidak sampai ke pohon
yang hidup. Rebuild menghasilkan bundel baru dan klien mengimpornya ulang, tapi
pohon yang ter-mount tetap merender implementasi sebelumnya — counter tetap
menyimpan state sementara labelnya basi. Sisa pekerjaannya ada di penukaran modul,
bukan di boundary-nya. Sampai itu selesai, barisnya berbunyi `terbuka`, bukan
`rilis`.

Tidak direncanakan, dan bukan kekurangan: React Server Components, islands,
streaming SSR, dan adapter deploy multi-platform. Keluaran compiler ini React
biasa di klien, dan itu fitur yang punya nama, bukan fitur yang belum selesai.

`hydra-lsp` adalah language server sungguhan: framing `Content-Length` di stdio,
diagnostik dari checker compiler itu sendiri (lewat `hydra check --json -`, jadi
tidak mungkin berbeda pendapat dengan build), hover, go-to-definition, dan rename
lintas berkas. `editors/vscode` adalah hal yang BERBEDA — syntax highlighting dan
diagnostik inline dengan memanggil biner `hydra`; ekstensi itu tidak menyalakan
server untukmu.

Yang dilakukannya: rename mengembalikan WorkspaceEdit untuk deklarasi DAN setiap
importer relatifnya, karena rename yang hanya menyentuh salah satunya membuat
import di berkas lain menamai sesuatu yang modulnya sudah tidak mengekspor.
Import dari paket ditolak dengan alasannya. Completion menawarkan nama di berkas
itu, builtin Python yang diturunkan compiler (dibaca dari `check.rs`, bukan
disalin), export asli sebuah modul setelah `from "x" import `, dan metode dari
literal list/dict/string setelah titik. Signature help menyebut parameter dan
argumen yang aktif, dari deklarasi callable itu sendiri.

Yang TIDAK dilakukannya, ditulis terang: formatting (pakai `hydra fmt`), semantic
tokens, code actions, workspace symbols. Request yang tidak diimplementasikan
menjawab `method not found`, bukan diam.
